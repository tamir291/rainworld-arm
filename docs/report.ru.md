RAIN WORLD НА ORANGE PI 4 PRO (ARM64, PowerVR BXM-4-64) — ЧТО СДЕЛАНО
=====================================================================
Итог: игра в полном разрешении 1366x768, ~59–60 FPS в геймплее (на GPU).
Было: ~1 кадр в несколько секунд.

Почему это вообще сложно
------------------------
- Rain World есть только под Windows x86_64 (Unity 2020.3). Плата — ARM64.
- Нужна цепочка: эмулятор x86_64 (box64) -> Wine (Windows-API) -> DirectX 11 -> какой-то GPU-API.
- Обычный путь (DXVK, DirectX->Vulkan) невозможен: драйверу PowerVR не хватает функций
  (robustness2/nullDescriptor, BC-текстуры, geometry shader). Zink (OpenGL поверх Vulkan) — тоже.
- Desktop OpenGL на этой плате — только программный llvmpipe (рисует CPU).
- Steam-клиент запустить не удалось: в ядре нет binfmt_misc (а ядро трогать нельзя).

Шаги
----
1. box64 v0.4.4 собран из исходников (-DARM64=1 -DBOX32=ON).
2. Игра скачана с аккаунта через DepotDownloader (нативный ARM64-клиент Steam-депо).
3. Wine 10.0 amd64-wow64 (сборка Kron4ek). Wine 11.x под box64 падает (assert host_page_mask).
4. Первый запуск: всё через llvmpipe -> 1–5 FPS. Профилирование по потокам показало,
   что 100% времени уходит в llvmpipe (пиксельные шейдеры на CPU).

5. Мод OpiPerf (BepInEx-плагин, src/rw-opiperf):
   - игра (движок Futile) и так рендерит камеру в текстуру; мод подменяет её на уменьшенную
     (1/4) и выводит растянутой без фильтрации — 4-6 FPS -> ~22;
   - маленькое окно игры + растягивание силами X-сервера (xrandr --scale-from, glamor на GPU):
     Unity/Wine делают несколько полноэкранных проходов на кадр, на CPU это дорого — ~22 -> ~44;
   - flatmode.txt (штатный флаг игры): плоские картинки меню вместо 15 слоёв с размытием;
   - замер FPS/фризов в лог, F7/F8 масштаб, F9 счётчик, отладочные команды через файл
     game/opiperf.cmd (scale/cap/cam/res/kill/restore/dump/story) — по ним шли все замеры.
   Итог программного режима: меню ~50, игра 30–58 FPS. Это режим `rainworld --cpu`.

6. GPU. У Wine есть свой Vulkan-рендерер (wined3d, не DXVK) — ему нужно меньше. Он отказывался,
   считая, что PowerVR тянет только DirectX 9.3: не хватало 4 флагов (geometryShader,
   multiViewport, pipelineStatisticsQuery, tessellationShader). Rain World — 2D, ему это не нужно.
   Написан Vulkan-слой VK_LAYER_OPI_fakefeatures (vk-layer/fakefeatures.c):
   - говорит Wine, что эти функции есть -> Wine включает DirectX 11;
   - при создании устройства убирает их, драйвер их не видит.
   Первая версия ПОВЕСИЛА ВСЮ ПЛАТУ: поверив в multiViewport, Wine ставил 16 вьюпортов в каждый
   пайплайн. Вторая версия санирует команды: вьюпорты/scissor -> 1, geometry/tess-стадии
   выкидываются, запросы pipeline statistics отклоняются. С ней: 59–60 FPS в 1366x768,
   CPU 170–250% вместо 600%. Это режим по умолчанию (`rainworld`).

7. Страховка на исходной плате: аппаратный watchdog (systemd RuntimeWatchdogSec=30s) и
   kernel.panic=10 — при зависании ядра плата сама перезагружается.

Что ещё было попробовано и отброшено
------------------------------------
- Snap-Steam от Canonical (FEX): нет snapd, и он тащит свой mesa без драйвера PowerVR.
- Закрепление потоков на быстрых ядрах (taskset): давало фризы по 5 с.
- Подмена отдельных шейдеров игры на простые (команда kill): на CPU помогало, но ломало картинку;
  на GPU не нужно.

Известные ограничения
---------------------
- Фризы 0.1–2.5 с при загрузке новой комнаты.
- DLC (Downpour/Watcher) без Steam-клиента, скорее всего, не активируются.
- GPU-режим — обходной путь в обход возможностей драйвера: если какая-то сцена использует
  вырезанное, возможен глюк или зависание. Тогда — `rainworld --cpu`.
- Курсор в игре скрыт (так делает сама игра в полноэкранном режиме).
